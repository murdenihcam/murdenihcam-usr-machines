**how to install (applies to any USR machine)**:
- _requirements:_ As I understand it, you can use **any** MD updated to [X.20B firmware available here](https://github.com/jmamma/MDX) to install machines from the folder of machines provided by MDX that comes in the firmware ZIP. This is also true of my E12-only sample playback machines, which work on your internal E12 samples, as well as NFX modules.
To install my *ROM and E12* machines or the ROM-only versions, you’ll need a Machinedrum UW on X.20B.

1. Locate a USR machine .syx that you want to install (eg one of the many that come with X.20 and/or my machine(s)--.syx to be found in respective folders here) and drag these into Sysex Librarian (or your sysex app of choice)
2. connect the MD to your midi interface 
3. FUNC+GLOBAL, FILE --> MACHINE MGR. Choose an empty slot, select RECV. It will say WAITING...
4. Using Sysex Librarian, play the .syx file(s) to the MD. You can select multiple .syx and play all at once; the machine bank will populate empty slots automatically. this is usually a very quick transfer as these are small files. The machine will then install. 
5. When you go to KIT-->EDIT, you may now see new machine categor(ies) corresponding to the new machine and you're good to go. Notably several of the ones from MDX will be found in existing categories like NFX and P-I. We’re limited to 16 slots but with a + drive you can have multiple Machine Banks.

**what it is**
A transient-detecting sample slicer and looper for the Machinedrum, compatible with the [X.20 firmware](https://github.com/jmamma/MDX) . This is most fun with longer samples but you can also get interesting textural results with shorter ones. the magic comes with plocking the SLNO parameter (slice number!) Not sure how useful this is on just E12. I have a version somewhere that does things like equal and random slices, let me know if you want that.
There are 3 versions:
-SMP-SL - all banks (UW only)
-SMP-SM - just rom (UW only)
-SMP-SN - just E12 (compatible with all models)

**parameters**:\
**PTCH** - half a semitone per step (±32 semitones). It changes speed as well. This interacts with TIME in interesting ways.

**SMPL** - Which sample: 1–48 are the UW ROM slots, E1–E21 the internal samples. Takes effect at the next trig.

**DEC -** 0: plays the slice once at full level. 1–126: decay from about 0.03 s to 30 s, with the slice looping in the PLAY direction while it’s audible. 127: no decay, loops forever.

**TIME** - 0: normal playback. Above 0, slows the slice down without changing pitch, using a timestretching algorithm. 42: half speed. After 50% turn, grain sizes get smaller127: frozen in place (infinite repeat). DEC at 0 means no amp envelope on the time, decay at higher levels, there is.

 - **NOTE:** Infinite decay continues when changing to a new pattern. This can be stopped when the same track receives a new trig. Note as well that until a new trig comes in the new pattern, the repeating sound from the previous pattern will take on the LEV of the new track (keeping them the same will not cause any level changes when switching patterns).

**PLAY** - Direction of playback. FWD: forwards. REV: backwards. BI: turns round at each end of the slice. When DEC loops, it’s checked at every loop, so you can change it while a slice is held.

**THRS** - Threshold for transient slicing to occur. higher means fewer slices made.

**SLIC** - Number of slices across the whole sample. Takes effect at the next trig.

**SLNO** - Which slice plays. Values above SLIC wrap round (for example SLNO 10 with 8 slices plays slice 2). Takes effect at the next trig

**TRACKS / CPU (v0.6):** certified with the MDS 1.1 certifier (MDX 2.0C). ## 3. SMP-GR[ANULATOR]
<img width="556" height="225" alt="SMP-GR" src="https://github.com/user-attachments/assets/cd42a033-916b-4d8d-b57e-77ed36815cac" />\

<img width="96" height="72" alt="SMP-GR_allbanks_web" src="https://github.com/user-attachments/assets/cfb39bdc-531a-4029-a639-638a4ca69ab5" />
<img width="96" height="72" alt="SMP-GM_rom_web" src="https://github.com/user-attachments/assets/063237c6-50d2-413e-8432-07ebcc7f4194" />
<img width="96" height="72" alt="SMP-G2_e12_web" src="https://github.com/user-attachments/assets/a3db6dfb-8d49-478f-b1dc-bf4a196dc1f1" />


**what it is**
An experimental granulator machine for the Elektron Machinedrum, compatible with the X.20 firmware

**NOTE:** Infinite decay/timestretch continues when changing to a new pattern. This can be stopped when the same track receives a new trig. Note as well that until a new trig comes in the new pattern, the repeating sound from the previous pattern will take on the LEV of the new track (keeping them the same will not cause any level changes when switching patterns).

**parameters**

**PTCH (pitch):** Playback pitch of the grains, in half-semitone steps. 64 is the original pitch, and the full range is ±32 semitones. Pitch modulation (LFO) also moves in half-semitone steps. Pitch doesn’t change scan speed or grain length.

**SMPL (sample):** Which sample to granulate. It’s read when the track is triggered. NOTE: this means when looping the sample on full DEC, changing SMPL will not change the sound until triggered again.

- SMP-GR: UW ROM slots 1–48, then the E12 samples E1–E21.
- SMP-GM: UW ROM slots 1–48.
- SMP-G2: E12 samples 1–21.

**DEC (decay):** Overall amplitude decay. The time to fade out ranges from about 30 ms to 30 s, and 127 holds the sound forever. The default is 64, about 1 second. Grains continue for as long as the sound lasts and loop back around again. This behavior is great with longer samples and loops.

 - **NOTE:** Infinite decay continues when changing to a new pattern. This can be stopped when the same track receives a new trig. Note as well that until a new trig comes in the new pattern, the repeating sound from the previous pattern will take on the LEV of the new track (keeping them the same will not cause any level changes when switching patterns).

**DENS (density):** Number of grains playing at once, on average, from 0.5 (sparse, with gaps) to 3. Up to about DENS 49, grains play one at a time at full quality (44.1 kHz). Above that, they overlap at half rate (22 kHz), up to 3 at a time at maximum. Volume is adjusted so busier settings don’t get louder.

**SEEK:** Where in the sample grains are taken from, from the start (0) to the end (127). With SCAN at 64, every grain starts here. The further SCAN is from 64, the less SEEK matters, because the position is moving on its own. Assigning an LFO to SCAN while this is happening does do some interesting stuff though.

**SCAN:** Moves the grain position through the sample over time. At 64, the position is locked. Higher values scan forward and lower values scan in reverse, up to about 2× normal speed. Small turns away from 64 give very slow, fine movement. At the end of the sample, the position wraps around to the other end.

**GRAN (grain size):** Length of each grain, from about 3 ms to 740 ms; 64 is about 46 ms. Each grain fades in and out linearly over roughly its first and last quarter.

**SPRY (spray):** Random variation in where each grain starts, around the SEEK/SCAN position. It reaches the whole sample at maximum. Above 64, grains also have a growing chance of playing backwards, up to 50% at 127.

**TRACKS / CPU (v0.6):** certified with the MDS 1.1 certifier (MDX 2.0C). Measured worst case per track, the same for SMP-GR, SMP-GM and SMP-G2: MKII 5,298 cycles, MKI 5,962 (5,255 with the program in SRAM). All 16 tracks need 3,000 (MKII) / 3,073 (MKI) or less, so with a granulator on every track plan on about **9 tracks on an MKII** and **8 on an MKI** (about 9 with the program in SRAM). Lighter machines on the other tracks leave room for more. These counts are estimates from the certified figures; the firmware does the actual budgeting.

## 4. NFX-MO[DULATOR]

<img width="431.5" height="196" alt="nfx-mo" src="https://github.com/user-attachments/assets/40ac44f0-23ee-4f05-8573-e42ddc7eb9a7" />\

<img width="96" height="72" alt="nfx-mo_web" src="https://github.com/user-attachments/assets/eb48353e-7ac2-4869-ac7d-fd29e3994dac" />

**what it is**
A multi-mode modulation effect, covering flanger, chorus, pitch and frequency shifting delays. Wild and exciting textural results abound: lots to explore and many spiralling sweet spots on this. 

**NOTE:** switching MODE does a short fade (about 1.5 ms out, 1.5 ms in) instead of jumping, so there’s a brief dip rather than a glitch. No trig is needed. A ringing feedback tail carries over into the new mode, but switching into a short delay (e.g. FLNG with low DLAY) can cut it off.

**parameters**
**MODE** - Toggles between 5 modes:

- **SPIN:** pitch-shifting delay. Feedback introduces spiral to the repeats. I love this one.
- **FLNG:** flanger
- **CHOR:** three-voice chorus (three taps 120° apart, feedback from all three). Low RATE with high FB gives a lovely clangy sound.
- **DBLR:** doubler: two slow, uneven, slightly detuned voices
- **BODE:** Bode shifter, a frequency shifting delay, causing clangy, inharmonic spirals. Another really exciting one.

**RATE** - LFO speed: 0.02–12 Hz in FLNG/DBLR, 0.05–10 Hz in CHOR. In SPIN it’s the shift, ±12 semitones. In BODE it’s the shift, ±1 kHz. 64 = no shift in SPIN and BODE.

**DPTH -** LFO depth in FLNG/CHOR/DBLR (up to 5 ms in CHOR). Window size (1.5–20 ms) in SPIN. In BODE: 0 = ring mod (static clang), 127 = pure shift (full spiral).

**FB -** Feedback. 64 = none, about 124 = unity (long trails), 125–127 = self-oscillation, below 64 = negative. In CHOR it tops out just below unity (0.98), so no self-oscillation there.

**SPRD -** Spread, per mode. FLNG adds a second tap. CHOR pulls the three voices’ delays apart (0 = the pure Monomachine-style sound). DBLR spreads the voice phase and delay. SPIN wobbles the shift (±25 cents). BODE wobbles the delay (±2 ms). This is a more subtle effect but interesting when modulated.

**ENTI -** Envelope time. This machine has a built-in envelope for modulating its delay time. At 64 (centre) it is deactivated. Left of centre = shorter delay times to longer, right = longer to shorter. Further from centre in either direction = longer envelope time. It is activated by trigs.

**DLAY -** Delay time, range dependent on mode (0.5–12 ms in CHOR).

**NBAL -** Input blend. Fully right = only the track just before, fully left = only two tracks before, centre = both. An empty neighbour track is ignored, so it can’t leak noise into the effect.

**TRACKS / CPU (v0.11):** certified with the MDS 1.1 certifier (MDX 2.0C). Measured worst case per track: MKII 4,381 cycles, MKI 5,942 (5,220 with the program in SRAM). All 16 tracks need 3,000 (MKII) / 3,073 (MKI) or less, so with NFX-MO on every track plan on about **10 tracks on an MKII** and **8 on an MKI** (about 9 with the program in SRAM). Lighter machines on the other tracks leave room for more. These counts are estimates from the certified figures; the firmware does the actual budgeting.

## 5. RAM-GR[ANULATOR]

<img width="96" height="72" alt="RAM-GR_web" src="RAM%20MACHINES/RAM-GR%5BANULATOR%5D/RAM-GR_web.png" />

**what it is**
Granulation of live audio — can be a granular delay or a player of held RAM audio. By default it is a granular delay (LIVE): the grains read just behind the recording, so the cloud follows the music. Turn SCAN up from 0 and a trig freezes the buffer instead, with up to 3 grains playing it.

**parameters**\
**PTCH** - grain pitch, ±32 semitones.

**MODE** - REC records all the time; HOLD stops recording and keeps the buffer.

**DEC** - fade after a trig, 127 = none.

**DENS** - grain overlap, 0.5 to 3 (up to 3 grains).

**SEEK** - where the playhead starts in the frozen buffer; in LIVE, how far behind the recording the grains read.

**SCAN** - 0 = LIVE (default). Above 0: playhead speed through the frozen buffer, -2x to +2x, 64 = still.

**GRAN** - grain length, 3-116 ms.

**SPRY** - random grain position and reverse chance.

**NOTE:** the slot is used as two halves: a trig freezes one and recording moves to the other, so every trig freezes fresh audio; retrig repeats keep the frozen audio. In HOLD a trig freezes what was recorded before the hold.

**TRACKS / CPU (v0.3):** MKII 4,454 cycles, MKI 4,912 (4,148 with the program in SRAM): **10 tracks on an MKII**, **10 on an MKI** (11 with SRAM).

## 6. RAM-P[ITCH] S[HIFTER]

**what it is**
A two-voice pitch shifter. Its own output is part of the main output it records, so the shifted sound comes back and is shifted again: a spiral whose depth follows the track's level, on top of FB.

**parameters**\
**PTCH** - voice 1, ±24 semitones (default an octave up).

**PTC2** - voice 2 likewise; 64 = off.

**ENTI** - a pitch swoop fired by trigs, up to ±12 semitones, settling in about 0.5 s; 64 = off.

**FB** - the shifted sound back into the buffer (shimmer).

**DLAY** - predelay, up to 200 ms.

**MODE** - REC records all the time; HOLD stops recording, so the last window keeps playing (a pitched freeze).

**WIN** - window, 12 ms (smooth, buzzy) to 370 ms (smeared, grainy).

**SCAT** - each read head lands up to a window further back at random when it jumps: grainy, scattered shifts.

## 7. RAM-ST[RETCH]

<img width="96" height="72" alt="RAM-ST_web" src="RAM%20MACHINES/RAM-ST%5BRETCH%5D/RAM-ST_web.png" />

**what it is**
The SMP-ST splice time-stretch on recorded audio: a trig plays the buffer through PTCH/DEC/TIME/STRT/END/GRAN/FLUX as on SMP-ST.

**parameters**\
**PTCH** - ±32 semitones, half a semitone per step.

**MODE** - 3 steps. Left REC (default): records all the time. Centre HOLD: stops recording and keeps the buffer. Right MREC: records with RAM-ST's own output muted (no spillover).

**DEC** - decay, 127 = hold.

**TIME** - playhead speed: 0 normal, 42 half, 127 frozen (pitch unchanged).

**STRT / END** - the window in the take; END before STRT plays it reversed.

**GRAN** - grain length (300-5000 samples).

**FLUX** - random grain position/length jitter.

**NOTE:** HOLD plays the whole buffer; REC plays the newest half, so a slowed take has time before new recording reaches it. Retrig repeats replay the same take; other trigs take a new one.

**TRACKS / CPU (v0.4):** MKII 3,362 cycles, MKI 3,919 (3,158 with the program in SRAM): up to **14 tracks on an MKII**, **12 on an MKI** (15 with SRAM).
